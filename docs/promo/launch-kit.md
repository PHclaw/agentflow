## 三、评论区话术（提前准备好，别现场编）

**Q：和 Dify 有什么区别？**
> 定位不同。Dify 是完整的 LLM 应用开发平台，生态和插件都更成熟，适合当基础设施。我这个更小：默认 SQLite 单机两个容器，重点放在"能交付文件"和"部署极简"上。如果你团队只有一台小机器、又不想专职运维，可能更合适；要复杂编排还是 Dify。

**Q：是不是就是个套壳？**
> 前端 React + ReactFlow，后端 FastAPI，工作流引擎是自己写的（`backend/app/services/workflow_runtime.py`），向量检索走 chromadb。可以 clone 下来看，代码都在。

**Q：能商用吗？**
> （按最终许可证回答，见 README 的「许可证」章节；技能目录是第三方社区资源，各自许可见 `THIRD_PARTY_NOTICES.md`。）

**Q：数据安全吗？会传到你们服务器吗？**
> 代码是自托管的，数据落在你自己的数据库里。模型调用走你配置的端点，可以指向本地 Ollama，连外网都不用出。演示站只是给你试界面，别往里放真实资料。

**Q：为什么不用 LangGraph / Dify 的工作流？**
> 需求只有六类节点，LangGraph 的表达能力过剩，多一层抽象就多一层调试成本。自研反而能做节点级状态实时回传。

**Q：收费吗？**
> 不收，开源。也没有云服务版，需要就自己部署。
