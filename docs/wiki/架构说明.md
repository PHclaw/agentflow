# 架构说明

> 完整版见仓库 [`docs/ARCHITECTURE.md`](https://github.com/PHclaw/agentflow/blob/master/docs/ARCHITECTURE.md)，这里只讲最需要知道的部分。

---

## 三层结构

```
接入层                FastAPI 应用层              数据与外部
Web / 安卓 / API  →   认证 · 工作流引擎 · 对话       SQLite（默认）
                      知识库 · 技能调度 · 产物       PostgreSQL + pgvector（可选）
                                                    Redis（可选）
                                                   模型端点 · ERP 数据源
```

没有 Celery Worker，也没有消息队列：当前所有任务在同一条异步请求链路里完成，单机部署不需要额外容器。

---

## 工作流节点

| 节点 | 作用 | 典型用法 |
|:--|:--|:--|
| 触发器 / 开始 | 流程入口 | 对话开始、接口触发 |
| LLM | 调用大模型生成内容 | 问答、改写、抽取 |
| 知识库 | 对指定库做语义检索 | 召回片段注入上下文 |
| 工具 / 技能 | 调用外部工具或 Skill | 查表、算数、跑脚本 |
| 条件分支 | 按变量取值路由 | 意图分流、兜底 |
| 回复 / 结束 | 组织输出并结束 | 统一出口、附引用来源 |

工作流引擎是自研的（`backend/app/services/workflow_runtime.py`），没有依赖 LangGraph——需求只有这几类节点，引框架反而多一层调试成本。

## 关键取舍

| 取舍 | 选择 | 理由 |
|:--|:--|:--|
| 默认数据库 | SQLite | 单机零依赖，复制文件即备份；规模上来再切 PostgreSQL |
| 向量检索 | chromadb / 外部 embedding 端点 | 不把 2GB 模型塞进镜像 |
| 模型接入 | 只认 OpenAI 兼容协议 | 一套适配吃下几乎所有主流与本地模型 |
| 技能扩展 | 目录 + `SKILL.md` | 非开发者也能按格式加能力 |
| 异步任务 | 目前同步链路 | 单机场景够用；队列化在路线图中 |

## 项目结构

```
agentflow/
├── backend/app/
│   ├── api/          # REST 路由
│   ├── core/         # 配置、安全、数据库
│   ├── models/       # SQLAlchemy 模型
│   └── services/     # 工作流引擎、技能执行、模型网关
├── frontend/src/
│   ├── pages/        # 落地页 / 控制台 / 工作流 / 对话 / 知识库 …
│   ├── components/   # UI 组件、布局、工作流节点
│   └── services/     # API 客户端
├── skills/           # 技能目录（每个含 SKILL.md）
├── docs/             # 文档
└── docker-compose.yml
```
